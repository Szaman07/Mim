Zero-Cost Reproducible Webcam Proctoring System

Proctoring-CV is an open-source computer vision system that monitors webcam video during online exams and reports three observable visual events: phone visible in frame, multiple people in frame, and head turned away from screen. It does not claim to detect cheating — it records timestamped visual observations with confidence scores and uncertainty diagnostics. The primary detector (YOLO11n) is trained entirely from scratch with no pretrained weights.

How it works

One visual pipeline, three bounded observations.

The runtime separates general object detection, geometric head-pose estimation, and timestamp-driven event logic so that each result remains inspectable.

The system never outputs CHEATING, SUSPICIOUS_PERSON, emotion, intent, identity, or audio analysis. When evidence is missing, it reports POSE_UNAVAILABLE or LOW_CONFIDENCE instead of guessing.

Step-by-step guides

How to execute each milestone.

Each guide is collapsed by default. Expand only the procedure you need.

GUIDE 01How to Set Up the Environment

Clone the project, install the package in editable mode, and run the complete test suite before changing any implementation code.

git clone https://github.com/Szaman07/Mim.git
cd Mim
pip install -e .
python -m pytest tests/ -v   # Should show: 41 passed
GUIDE 02How to Get the Dataset

Begin with the synthetic dataset to validate the local path and schema. Download the filtered real data only after the local workflow passes.

# Quick synthetic dev dataset (instant, for testing)
python scripts/download_dataset.py --source sample --output data/datasets/coco2017_filtered_v1

# Real filtered COCO 2017 (downloads ~1GB)
python scripts/download_dataset.py --source coco_val2017 --output data/datasets/coco2017_filtered_v1

# Validate dataset integrity
python scripts/validate_dataset.py --root data/datasets/coco2017_filtered_v1
GUIDE 03How to Train on Google Colab

Mount Drive before training. The runtime is disposable; Drive stores the experiment configuration, checkpoints, logs, and metrics.

# 1. Mount Drive
from google.colab import drive
drive.mount('/content/drive')

# 2. Clone and install
!git clone https://github.com/Szaman07/Mim.git /content/Mim
%cd /content/Mim
!pip install -e .

# 3. Preflight gate (must show decreasing loss)
!python scripts/tiny_overfit.py --config configs/experiments/yolo11n_scratch_coco.yaml --epochs 5 --device 0

# 4. Full training
!python scripts/train.py \
    --config configs/experiments/yolo11n_scratch_coco.yaml \
    --experiment-id yolo11n_scratch_coco_v1_seed42 \
    --drive-root /content/drive/MyDrive/proctoring_cv \
    --mode full
GUIDE 04How to Resume After Colab Disconnects

Use exact resume only when returning to the same experiment and unchanged configuration. Use a new branch when changing data, architecture, or hyperparameters.

python scripts/resume_training.py \
    --experiment-dir /content/drive/MyDrive/proctoring_cv/experiments/yolo11n_scratch_coco_v1_seed42 \
    --checkpoint last.pt \
    --resume
GUIDE 05How to Evaluate a Trained Checkpoint

Evaluate on validation data while selecting configurations. Preserve the locked test set for the final one-shot result.

python scripts/evaluate.py \
    --checkpoint experiments/yolo11n_scratch_coco_v1_seed42/checkpoints/best.pt \
    --split val
GUIDE 06How to Deploy the Django App

After a checkpoint has been selected, integrate the documented Django example into an existing Django project and configure deployment infrastructure separately.

pip install django channels daphne
pip install -e /path/to/Mim

Event engine

State is earned through time, not inferred from one frame.

Each observable event must persist long enough to become active and must recover long enough to end.
